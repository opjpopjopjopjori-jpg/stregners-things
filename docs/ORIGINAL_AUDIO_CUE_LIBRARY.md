# Original Audio Cue Library

## Ownership and scope

All files in `assets/riftcompanions/sounds/companions`, `sounds/ui`, and `sounds/ambience` are deterministic synthesized original OGG Vorbis assets generated by `tools/generate_original_audio_library.py`.

They contain no actor voice, voice imitation, show dialogue, soundtrack, extracted scene audio, or third-party sample library.

## Runtime action mapping

`CompanionPresentationSoundService` plays only confirmed server-side presentation cues after an existing visual action is requested. It has no gameplay authority.

| Trigger | Cue | Cooldown behavior |
|---|---|---|
| Guard posture | `guardian_guard_signal` | bounded per entity |
| Confirmed melee visual | `guardian_melee_swing` | bounded per entity |
| Hit reaction | `guardian_impact` | bounded per entity |
| Retreat signal | `guardian_retreat` | bounded per entity |
| Seer notice/focus/release/recovery | matching Seer cue | bounded per entity |
| Gifted notice/focus/push/shield/rescue/exhaustion | matching Gifted cue | bounded per entity |
| Scout point/lookout/anchor | matching Scout cue | bounded per entity |
| Accepted plan | `ui_plan_accept` | one confirmed UI cue |
| Safe Mode enable | `ui_safe_mode` | one confirmed UI cue |

The long ambience loops are packaged for future safe-base mix testing. They are not auto-looped by current source logic, so they cannot become ambient spam before a runtime mix gate exists.

## Settings and accessibility

```text
companion_audio_enabled = true by default
hive_audio_enabled = true by default
```

Disabling `companion_audio_enabled` suppresses companion and UI presentation cues but never changes AI, damage, power validation, plans, inventory, Safety Gates, or HUD/chat fallback.

Every important cue has a non-audio fallback through animation, HUD, Journal, chat, or visual state. No cue is color-only or audio-only information.

## Mix rules

- Alert and rescue cues must remain clearer than ambience.
- Per-entity cooldown prevents action sound spam.
- No long ambient loop may start automatically during combat.
- Low Effects does not disable state information.
- A future runtime mix must honor Minecraft master/category volume settings.

## Required runtime tests

1. Confirm every registered cue resolves from `sounds.json` without missing-sound warnings.
2. Confirm `companion_audio_enabled = false` suppresses companion cues only.
3. Trigger rapid melee/hit/focus actions and verify cooldown prevents stacking.
4. Trigger plan acceptance and Safe Mode once each; verify cue plus HUD/chat fallback.
5. Test low master volume, muted audio, and Low Effects; gameplay information remains readable.
6. Verify no cue uses a show-recognizable melody, actor voice, or copied asset.
7. Check spatial volume and crowd behavior with two active companions.

## Non-claims

The assets are packaged and registered in source, but no runtime audio mix, speaker balance, subtitle timing, or player acceptance result is claimed until a Minecraft client test occurs.
